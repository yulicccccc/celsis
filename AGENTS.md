# AGENTS.md — Celsis Automation Development Contract

This file is binding guidance for AI coding agents working in this repository.

## 1. Safety boundary

Never claim this system is GxP validated unless a documented validation package explicitly says so.

Current wording:

> Prototype — Not validated for GxP use.

Never automate Save, Submit, approval, or signature without an explicit future approved requirement and validation.

## 2. Source truth

Do not generate a result from memory when source files are available.

Before entry:

- match Daily Control and Workload,
- use Daily Control for ATP,
- use Workload control blocks for media-specific controls/cutoffs.

## 3. Locked Celsis rules

- `CV >= 30%` is invalid.
- Max RLU means the maximum of the report's `RLU` result column.
- Never use the maximum of RLU1/RLU2 as the entry result.
- MF = `m`; DI = `d`.
- Volume Placement: MF volume MUST be in Filtered volume field (`SubmissionTestResults_3__Value`) with DI field empty; DI volume MUST be in Added volume field (`SubmissionTestResults_4__Value`) with MF field empty.
- Note-Derived Volume Canonical Format: When verifying sample volume from Test Notes, the authoritative test volume follows `Method: [DI|MF]. <X> mL of sample added/filtered per media` (or `<X> mL of sample added/filtered per media`). This `<X> mL` MUST match the LIMS Added/Filtered volume field. Intermediate prep ratios (e.g. `5mL sample + 15mL Tween80`) are modification notes, NOT the final test volume per media.
- Groups are dynamic.
- Preserve rerun/run/media lineage.
- No silent OCR guesses.
- Base ETX is used for LIMS lookup; raw source labels remain traceable.
- Automated Approval Cadence: When batch automated approval is authorized by the user, default to approximately 1 minute per sample (~50-70s randomized sleep) to ensure realistic GxP audit trail spacing, while preserving non-blocking Enter-to-skip control.

## 4. Data Entry UX contract

Default batch delivery:

1. bookmark-downloader `.html`,
2. Enter-only `.ps1`,
3. review table,
4. Test Note(s),
5. optional complete `.zip`.

Bookmarklet:

- light blue pending,
- light yellow next,
- light green opened,
- high-contrast dark links,
- auto retry scan,
- Re-scan button.

PowerShell:

- one Enter per sample,
- `Q` to stop,
- no YES/NEXT words,
- auto-copy correct note,
- no automatic Save.

## 5. Bookmarklet implementation contract

Always HTML-escape the `javascript:` URL inside downloader HTML.

Search order for test link:

1. `/SubmissionTest/Details/`
2. visible `Celsis Sterility Test`
3. SubmissionTest-like href
4. historical link-index fallback

ETX matching should normalize:

- whitespace,
- zero-width characters,
- case.

Do not report “missing” after a single instantaneous scan. Retry for asynchronous page loading and provide manual Re-scan.

## 7. Validation contract

Synthetic tests are not Golden validation.

Golden expected results must be independently human-confirmed from the source, not generated by the parser under test.

Preferred Golden comparison:

```text
Human Expected == JS Engine == Python Reviewer
```

Use exact equality for integer RLU fields.

## 8. Repo hygiene

Do not commit:

- production PDFs,
- WKL/TXT source exports,
- browser session data,
- credentials,
- cookies,
- screenshots containing live internal data,
- `node_modules`,
- portable Node binaries.

Use synthetic/fake ETX identifiers in public examples.

## 9. Change discipline

When changing a locked rule:

1. identify the rule,
2. explain why source evidence requires change,
3. add/update a regression case,
4. update PRD / rules docs,
5. update CHANGELOG,
6. rerun full tests,
7. do not silently alter existing expected results.
